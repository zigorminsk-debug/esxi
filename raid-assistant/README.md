# ESXi RAID Assistant для Windows

Отдельная программа на Go с локальным HTML-интерфейсом помогает подготовить **LSI Storage Authority / Light Weight Agent (LSA/LWA)** для совместимого контроллера на ESXi. После установки и настройки администратором интерфейс агента может быть доступен на `https://IP-ESXi:35557`. Это не встроенный универсальный порт ESXi и не средство управления любым RAID.

## Возможности и ограничения

- Подключение к **непосредственному хосту ESXi**, не к vCenter: версия и сборка, сервер, адаптеры и их PCI/subsystem ID, драйверы, доступные datastore, службы и правила firewall, по возможности список VIB, acceptance level и состояние Secure Boot, сообщённое firmware (API ESXi 8.0 U3). Проверка TCP 35557 показывает только доступность TCP, не работоспособность LSA.
- Только чтение: программа создаёт обычный сеанс API и временное представление инвентаря. Она **не устанавливает VIB, не включает SSH, не меняет firewall или RAID и не перезагружает хост**. Иногда API не разрешает получить отдельные данные — они помечаются как неизвестные, а не выдумываются.
- Небольшой проверяемый каталог: **ESXi 8.0 U1/U2/U3** и розничные Broadcom MegaRAID **9560-8i, 9580-8i8e, 9524-8i, 9520-2M2** при совпадении всех четырёх PCI ID и активном HBA с драйвером. Это кандидаты, а не гарантия поддержки: firmware, точную сборку, OEM, состояние RAID, Secure Boot и подпись необходимо подтвердить отдельно. Данные firmware о Secure Boot не являются TPM-аттестацией. README конкретного архива перечисляет только эти обновления ESXi; базовый 8.0 GA, ESXi 7/9 и другие модели автоматически не выбираются.
- Для неизвестного, OEM (например Dell PERC), неподключённого или несовместимого по версии контроллера интерфейс объясняет, почему автоматический подбор остановлен, и предлагает обратиться к OEM. Отсутствие в каталоге **не доказывает** несовместимость. Пакет LWM для мониторинга не подменяет LSA/LWA для управления.
- При совпадении можно прочитать условия Broadcom и подтвердить согласие, после чего приложение скачает официальный ZIP, ограничит объём распаковки, сверит зафиксированный SHA-256 и извлечёт единственный VIB `lwmd` для ESXi 8. Можно импортировать ZIP/VIB вручную. Подлинность произвольного импорта не подтверждается.
- Инструкция формируется по результатам конкретного хоста и включает проверку файла, передачу в выбранный datastore, dry-run, ручную установку, проверку службы и ограничение firewall доверенным IP/CIDR. Пакет не устанавливается, пока администратор сам не выполнит действия. Инструкцию можно копировать или сохранить как Markdown; команды копируются отдельно.
- Свободное место в datastore не означает наличие места в bootbank. Проверяйте резервные копии, состояние массива, совместимость, зависимости, подпись, maintenance mode и требования производителя. README данного выпуска запрещает live-install и требует планировать перезагрузку. Ошибка подписи, неизвестное происхождение или неудачный dry-run — повод остановиться, а не применять `--force` или `--no-sig-check`.

## Запуск

1. Нужны Windows 10/11 x64 и актуальный [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/en-us/microsoft-edge/webview2/); на многих системах он уже установлен. Скачайте `ESXi-RAID-Assistant-0.1.0-windows-x64.exe` из отдельного релиза RAID Assistant и запустите. Установка Python, Go или сервера на ПК не нужна.
2. Введите IP/DNS ESXi и учётную запись с правами просмотра аппаратной конфигурации. Для части ESXCLI-запросов могут понадобиться дополнительные права. Учётная запись для последующей ручной установки должна иметь соответствующие административные права; не используйте чрезмерные права без необходимости.
3. Нажмите **«Проверить сертификат»**. До проверки доверия программа не отправляет логин и пароль. При самоподписанном сертификате сравните SHA-256 с независимо полученным отпечатком, например через доверенную локальную консоль хоста или iDRAC/iLO:

   ```sh
   openssl x509 -in /etc/vmware/ssl/rui.crt -noout -sha256 -fingerprint
   ```

   Введите именно независимо проверенный отпечаток. Просто скопировать показанный программой отпечаток недостаточно. Сертификат должен быть действителен по времени. Пароль передаётся только выбранному ESXi в защищённом сеансе API, не записывается самим приложением в файл и удаляется из поля после попытки входа. Перед загрузкой формы в WebView2 отключаются сохранение паролей и общее автозаполнение; если Runtime не поддерживает эти настройки, запуск останавливается.
4. Изучите данные и причины предупреждений. Для кандидата откройте страницу модели, README и лицензию Broadcom. После личного согласия нажмите **«Скачать пакет»**, либо выберите уже скачанный официальный ZIP/VIB. При невозможности загрузки используйте официальный сайт и импорт; приложение не обходит лицензии или ограничения доступа.
5. Выберите доступный datastore и введите доверенный адрес администратора или сеть CIDR для правила firewall. Команды не генерируются для неизвестного datastore; `0.0.0.0/0` и `::/0` не принимаются. Изучите и сохраните персональную инструкцию. Команды выполняются **только вручную** в согласованное окно обслуживания.

Файлы сохраняются в `%USERPROFILE%\Downloads\ESXi-RAID-Assistant\<сеанс>`. Отчёты и скачанные файлы могут содержать имена, адреса и сведения об инфраструктуре — относитесь к ним как к внутренним данным. Пароль в отчёт не включается. Размер текста меняется кнопками **А− / А+**.

## Источник пакета и доверие

- [Официальная страница пакета и лицензия Broadcom](https://docs.broadcom.com/docs/1232745889), [README](https://docs.broadcom.com/docs/1232745888), [инструкция по LWA для ESXi 8](https://techdocs.broadcom.com/us/en/storage-and-ethernet-connectivity/enterprise-storage-solutions/lsa-lsi-storage-authority-software/2-18/Managing-Light-Weight-Agent/Installing-LWA-on-VMware-ESXi/Installing-LWA-on-VMware-ESXi8x.html).
- Конкретный выбранный выпуск: LSA MR 7.38 `008.018.012.000`. SHA-256 архива `b11f8b5cf11d918c652dfc3b6a6caa231df63ddf2aab17ceaf074cf9d72679a5` — **локально зафиксированный отпечаток** копии, полученной с Broadcom 01.11.2026; это не опубликованная Broadcom подпись. При несовпадении автоматическая подготовка остановится. Проверка VIB на хосте и согласование с производителем всё равно обязательны.
- Если в будущем Broadcom заменит или удалит этот файл, используйте сайт производителя, проверьте совместимость и импортируйте актуальный пакет; импорт обозначается как непроверенный, если его хеш не совпадает с зафиксированной копией.

EXE подписывается тем же постоянным **публичным лабораторным** сертификатом, что и ESXi Atlas. Его закрытый ключ по указанию владельца находится в открытом репозитории, поэтому подпись не обеспечивает защищённую идентификацию издателя и возможны предупреждения SmartScreen/Windows. Для production нужен отдельный защищённый сертификат. Автообновления отдельного RAID Assistant в версии 0.1.0 нет: закрытую программу можно обновить заменой EXE после самостоятельной проверки источника и совместимости.

## Проверка и разработка

```sh
cd raid-assistant
go test -race ./...
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -ldflags '-s -w -H windowsgui' -o ESXi-RAID-Assistant.exe ./cmd/raid-assistant
```

`go run ./cmd/preview` запускает **только демонстрационный** интерфейс с вымышленными данными, без соединения с ESXi и без загрузок. Используйте этот сервер только в доверенной сети. UI-тесты: `npm ci && npm run test:ui` (после установки Chromium для Playwright и запуска preview). GitHub Actions выполняет Go-тесты, сценарии браузера, сборку/подпись Windows и проверку WebView2 на Windows runner. Используется govmomi simulator: это не проверка на настоящем ESXi. В репозиторий не входит ни пакет Broadcom, ни учётные данные.

Локальные изменения WebView2 bridge и лицензия стороннего кода: [third_party/go-webview2/LOCAL_CHANGES.md](third_party/go-webview2/LOCAL_CHANGES.md).

Дополнительно: [ограничения управления системными правилами ESXi 8](https://knowledge.broadcom.com/external/article/384384/error-can-not-enabledisable-this-ruleset.html). Перед изменением `lwmd` проверьте столбцы **Enable/Disable configurable** и **Allowed IP configurable**.
