# ESXi RAID Assistant 0.2.3 для Windows

Отдельная программа на Go с локальным HTML-интерфейсом помогает обследовать **непосредственный хост ESXi 8**, посмотреть отчёты RAID и подготовить ручную установку **LSI Storage Authority Light Weight Agent (LSA/LWA)** для подходящего Broadcom MegaRAID. После правильной установки совместимого агента его интерфейс может открываться по `https://IP-ESXi:35557`. Это не универсальный порт ESXi и не средство управления любым контроллером.

**Программа не устанавливает пакеты на ESXi, не меняет RAID или firewall, не включает SSH и не перезагружает сервер.** Установка и все изменения — только вручную, после решения администратора. Возможности LSA могут изменять массив и уничтожать данные.

## Что нового

- **Версия 0.2.3:** полный PCI ID `1000:005d / 1000:9361` отображается как MegaRAID SAS 9361-8i (SAS3108), включая случай, когда состояние HBA в ESXi API равно `unknown`. Модель по PCI ID не подтверждает здоровье массива, firmware или поддержку пакета. Для 9361-8i автоматический выбор LWA остаётся выключенным: [README MR 7.38](https://docs.broadcom.com/docs/1232745888) не перечисляет эту модель. Для 9361 показаны [HCL](https://compatibilityguide.broadcom.com/detail?program=io&productId=35237&persona=live), [каталог производителя](https://www.broadcom.com/support/download-search?dk=&pa=&pf=RAID+Controller+Cards&pg=Storage+Adapters%2C+Controllers%2C+and+ICs&pn=MegaRAID+SAS+9361-8i&po=) подсказка о найденных именах StorCLI в списке VIB и безопасная команда просмотра, если совместимый StorCLI64 **уже установлен** на ESXi 8. Если в сервере одновременно обнаружен кандидат серии 95xx, он не означает поддержку 9361.
- **Версия 0.2.2:** собственная иконка у EXE, окна и на панели задач. Исправлена ошибка проверки результата Windows COM, которая могла мешать запуску даже при установленном WebView2. При другой ошибке окно показывает этап и код, а не утверждает, что Runtime отсутствует.
- При отсутствии WebView2 программа автоматически скачивает официальный Bootstrapper по HTTPS у Microsoft и проверяет цифровую подпись Windows и издателя Microsoft Corporation. Она **спрашивает разрешение перед установкой на Windows-ПК** и после установки повторно проверяет наличие Runtime. Это не установка на ESXi. Для загрузки и установки нужен интернет; Windows может запросить разрешение. При отсутствии сети можно на другом ПК скачать с [сайта Microsoft](https://developer.microsoft.com/microsoft-edge/webview2/) Evergreen Standalone Installer x64 и перенести его. Если Runtime уже установлен, программа не скачивает его автоматически и не переустанавливает.
- SSH сообщает об отдельно обнаруженном изменении ключа или ошибке входа рядом с кнопкой, а не только во временном уведомлении. Поддержана одношаговая password/keyboard-interactive аутентификация; OTP и дополнительные запросы программа не обрабатывает, повторно пароль автоматически не отправляет. Выявленная ошибка входа не доказывает неверный пароль: проверьте права/политику SSH и блокировку учётной записи.
- Подсказка для HPE Smart Array выбирает идентификаторы самого контроллера, а не соседнего AHCI, но не подтверждает совместимость ESXi или пакета.
- В версии 0.2.1 подключение начинается кнопкой **«Подключиться»** после ввода IP, логина и пароля. Отдельный файл сертификата и ввод отпечатка больше не обязательны. Состояние и ошибки остаются рядом с кнопкой.
- Диагностика через API ESXi: версия/build, сервер, PCI ID и драйверы, доступные datastore, службы, firewall, список VIB и, при наличии данных, Secure Boot. Есть отдельная проверка TCP, TLS-сертификата и HTTP-ответа 35557 без передачи пароля. Факты и возможные причины разделены: открытый порт или TLS сами по себе не подтверждают LSA и исправность RAID.
- Импорт снимка **StorCLI / StorCLI2 JSON** или **HPE SSACLI TXT**; показ распознанных контроллеров, логических и физических дисков, состояний и предупреждений. Форматы отличаются у разных версий: неполный или нераспознанный отчёт не считается исправным массивом.
- Необязательное получение отчёта по SSH только после отдельного разрешения и независимой сверки **SSH host key**. Применяются фиксированные команды чтения, произвольный shell-код и изменение конфигурации не выполняются. Утилита и SSH должны уже быть доступны на хосте. Поддержка конкретных путей и форматов не гарантирована. Для StorCLI2 на ESXi 8 используется ESXCLI-плагин и системный обзор: в нём может не быть сведений о дисках.
- Осторожное распознавание Dell PERC, HPE Smart Array и Lenovo по названию или OEM subsystem ID. Это подсказка для обращения к производителю, не доказательство поддержки пакета или наличия веб-порта.
- Локальный каталог возможностей Broadcom/VMware и партнёров с назначением, ограничениями, ссылками на официальные источники и отметками найденных VIB. Это не полная база совместимости и **не автоматический установщик**. Подробное исследование — [ESXI-8-EXTENSIONS.md](ESXI-8-EXTENSIONS.md).
- Связь логического RAID-диска с VMFS datastore и видимыми ВМ показывается только при уникальном точном совпадении NAA в отчёте и инвентаре хоста. Для импорта нужно подтвердить, что снимок получен именно с этого хоста. NFS, vSAN, RDM, отсутствующие права и ВМ/диски вне видимого инвентаря могут не отражаться; список ВМ на datastore не доказывает расположение каждого виртуального диска.
- Список хостов без сохранения паролей; локальная история последних 200 кратких событий; мониторинг одного хоста по TCP/TLS 35557 либо SSH с интервалом 60–3600 секунд и необязательными системными уведомлениями **пока приложение запущено**. SSH-пароль для мониторинга остаётся только в оперативной памяти до остановки. Это не фоновая служба и не замена промышленной системе мониторинга.
- Проверка наличия новых релизов RAID Assistant на GitHub и переход к ним для **ручной** загрузки; автоматической установки обновлений нет. Кнопки копирования команд, сохранение инструкции в Markdown и подтверждаемая отправка части инструкции через Telegram. Размер текста меняется кнопками **А− / А+**.
- В мастере есть реальные скриншоты из публикаций OVHcloud со ссылками: загрузка ISO в datastore и пример списка firewall. Они показывают примеры интерфейса с неизвестной сборкой, не доказывают установку VIB или наличие `lwmd`. Настоящего проверенного снимка `lwmd` на ESXi 8 у нас нет; при желании замените первый пример собственным PNG/JPEG до 1 МиБ.

## Системные требования и доверие

Windows 10/11 x64, [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/en-us/microsoft-edge/webview2/), доступ к ESXi из доверенной сети. Скачайте `ESXi-RAID-Assistant-0.2.3-windows-x64.exe` из отдельного предварительного релиза RAID Assistant. Go или Python на ПК не требуются.

EXE подписывается постоянным **публичным лабораторным** сертификатом ESXi Atlas. По решению владельца его закрытый ключ находится в публичном репозитории, поэтому такая подпись **не доказывает подлинность издателя**; возможны предупреждения Windows/SmartScreen. Для production нужен отдельный защищённый сертификат. Контрольная сумма позволяет обнаружить случайное изменение относительно источника, но не заменяет проверку происхождения.

У нас не было доступа к реальному ESXi/RAID-оборудованию. Автотесты используют имитацию govmomi/SSH и Windows WebView2 smoke, а не проверку на вашем сервере. В Windows CI проверены подпись и запуск официального загрузчика при уже установленном Runtime; установка на чистой Windows без Runtime ещё не испытана. Начинайте с тестовой среды, подтверждайте модель, версии, показания и резервные копии самостоятельно.

## Как обследовать хост

1. Запустите программу, введите IP-адрес самого ESXi (не vCenter), логин и пароль и нажмите **«Подключиться»**. Обычно используется порт HTTPS 443. При желании сохраните название, адрес и логин кнопкой «Сохранить хост» — пароль в профиль не записывается.
2. Программа сначала связывается с сервером без пароля. Если системная проверка HTTPS прошла, вход начнётся автоматически. Для распространённого самоподписанного или истёкшего сертификата появится предупреждение: **подлинность сервера может быть не подтверждена, а при подмене пароль может быть перехвачен**. Продолжайте только в доверенной сети и только если понимаете риск; «Отмена» не отправляет пароль. Если сертификат истёк или ещё не действителен, также проверьте часы компьютера и хоста.
3. После входа изучите адаптеры, инвентарь и предупреждения. Если подключение или вход не удались, пояснение останется рядом с кнопкой: проверьте IP, связь с портом 443, логин, пароль и права. Пароль очищается из поля после попытки и не сохраняется в файл. Встроенный WebView2 не сохраняет пароли/автозаполнение; если эти настройки недоступны, приложение не запускается.
4. В разделе **«Диагностика»** нажмите проверку порта 35557. Последовательно изучите установку `lwmd`, состояние службы, правило firewall, TCP, TLS и HTTP. Неполученное состояние не равнозначно отключённой службе; в некоторых сборках ESXi 8 `esxcli daemon info get -s lwmd` может ничего не вывести — дополнительно проверьте Host Client и журналы. Сертификат на 35557 может отличаться от сертификата на 443: проверяйте его отдельно, прежде чем вводить пароль в браузере.

### Дополнительная защита (необязательно)

Если заранее знаете SHA-256 сертификата из **независимого доверенного** источника, раскройте «Дополнительная проверка» и введите его. Например, через доверенную консоль сервера/BMC:

```sh
openssl x509 -in /etc/vmware/ssl/rui.crt -noout -sha256 -fingerprint
```

Несовпадение остановит вход до передачи пароля. Без независимой сверки программа после вашего подтверждения временно закрепляет отпечаток, полученный при первом контакте, и проверяет его на каждом новом TLS-соединении. Это предотвращает незаметную смену сертификата между предварительным соединением и входом, **но не подтверждает подлинность первого контакта** и не защищает от уже присутствующей подмены. Поле отпечатка не сохраняется в профиль. Истёкший или ещё не действующий сертификат принимается только после отдельного подтверждения, даже если отпечаток совпал.

## Состояние дисков: импорт или SSH

**Вариант А — без SSH из программы.** Получите отчёт подходящей утилитой производителя и сохраните его на Windows-ПК. В разделе **«RAID и диски» → «Выбрать JSON / TXT»** выберите StorCLI/StorCLI2 JSON или текст HPE SSACLI. Кнопки рядом копируют примеры команд; используйте подходящую версию утилиты и синтаксис по документации OEM. Программа читает файл до 10 МиБ, не исполняя его содержимое. Отчёт — снимок, который может устареть или содержать конфиденциальные данные.

**Вариант Б — чтение по SSH.** После обследования хоста раскройте «Получить отчёт по SSH», нажмите получение host key и независимо сравните его с доверенной консолью/BMC. Введите проверенный SHA256-отпечаток, логин и пароль SSH, выберите подходящую заранее установленную утилиту и явно разрешите чтение. Программа сама SSH не включает. Неверный ключ останавливает соединение до аутентификации. SSH-вход и запуск утилиты могут попасть в системный аудит хоста. При ошибке входа не делайте много повторных попыток: проверьте доступ и блокировку учётной записи. Если сервер требует OTP или другой сложный запрос, используйте импорт отчёта. Не все варианты вывода и пути поддерживаются.

Чтобы показать возможные связи с ВМ, сначала обследуйте этот же хост, затем импортируйте его актуальный отчёт или выполните SSH-чтение. При импорте отметьте подтверждение принадлежности и нажмите **«Найти связи»**. Если NAA отсутствует, не уникален или не совпал с VMFS extent, связь не придумывается.

### MegaRAID SAS 9361-8i

После сканирования адаптер с полным PCI ID `1000:005d / 1000:9361` будет назван **MegaRAID SAS 9361-8i** и помечен как «Модель по PCI», а не как кандидат пакета. `unknown` — неизвестное состояние адаптера по API, а не диагноз дисков. В разделе пакета откройте совместимость Broadcom и выберите точный ESXi release, затем проверьте сервер, драйвер и firmware. Раздел загрузок относится к модели в целом; каждый архив нужно сверять отдельно с его README и конкретным ESXi/OEM. Неперечисленная модель не обязательно несовместима, но оснований автоматически выбрать MR 7.38 нет. Не применяйте LWM вместо LWA и не устанавливайте пакеты наугад.

Если на ESXi 8 уже установлен совместимый StorCLI64 по `/opt/storcli/bin/storcli64`, нажмите «Открыть чтение RAID по SSH», проверьте SSH host key независимым способом и отдельно разрешите чтение. Программа выполняет только фиксированную команду, но поддерживает не все версии пути/формата. В интерфейсе есть и копируемая команда просмотра `/opt/storcli/bin/storcli64 show nolog`; её ответ можно посмотреть вручную. Если утилита отсутствует, убедитесь в совместимости по документации/OEM перед любым изменением сервера. Проверка на реальном 9361-8i не проводилась. Наличие/совместимость LWA для вашей сборки и доступ через 35557 остаются не подтверждены.

## LSA/LWA: персональная инструкция для 35557

1. Автоподбор ограничен ESXi **8.0 U1/U2/U3** и четырьмя розничными моделями: MegaRAID **9560-8i, 9580-8i8e, 9524-8i, 9520-2M2**. Необходимы совпадение четырёх PCI ID и активный HBA с драйвером. Это **кандидат, не гарантия совместимости**: отдельно сверяйте firmware, конкретный build, модель, OEM и подпись. ESXi 8.0 GA и другие семейства автоматически не выбираются.
2. Если найден кандидат, откройте его страницу, [README](https://docs.broadcom.com/docs/1232745888) и [лицензию Broadcom](https://docs.broadcom.com/docs/1232745889). После личного согласия нажмите **«Скачать пакет»** или импортируйте скачанный официально ZIP/VIB. При неизвестном/OEM контроллере программа объяснит остановку: используйте поддержку OEM, а не случайный пакет. LWM для мониторинга не является заменой LSA/LWA для управления.
3. Выберите доступный datastore и доверенный IP/CIDR административной станции, прочитайте персональную инструкцию. Сначала проверьте резервные копии, здоровье массива, firmware, подпись и зависимости; подготовьте окно работ, обслуживание и план отката. Свободное место datastore не доказывает наличие места в bootbank.
4. Если все условия выполнены, **вручную** загрузите подготовленный VIB через Host Client → Storage → datastore → Datastore browser → Upload. Включайте SSH вручную только на время работ. Сравните хеш, изучите сведения VIB и выполните предложенный `--dry-run`. При ошибке подписи/зависимостей остановитесь; не применяйте `--force`, `--no-sig-check` и не снижайте acceptance.
5. Только после согласования вручную выполните установку, maintenance mode и необходимую перезагрузку по README. Данный выпуск запрещает live-install и требует перезагрузку. Затем проверьте VIB, службу и firewall. Сначала посмотрите все порты правила `lwmd` и возможность изменения Allowed IP/Enable; в нём могут присутствовать исходящие 25/465. Не отключайте firewall целиком и не публикуйте 35557 в Интернет.
6. С доверенного ПК откройте `https://IP-ESXi:35557`, независимо проверьте сертификат этой службы и после работ выключите временный SSH. Создание/удаление RAID — отдельные опасные действия, не часть автоматизации помощника.

Загружаемый архив MR 7.38 `008.018.012.000` сверяется с локально зафиксированным SHA-256 `b11f8b5cf11d918c652dfc3b6a6caa231df63ddf2aab17ceaf074cf9d72679a5`, а размер и глубина распаковки ограничены. Это отпечаток копии, полученной с Broadcom, **не подпись Broadcom**. Произвольный импорт помечается как неподтверждённый. Если поставщик сменил файл, проверьте актуальный официальный пакет и воспользуйтесь импортом.

## История, мониторинг и приватность

Раздел «Мониторинг» показывает историю и позволяет её очистить. История хранит краткие сводки, адреса и время, а не исходные отчёты или пароли. «Мониторинг 35557» не равен мониторингу дисков. Для SSH-режима нужны новое разрешение, проверенный host key и пароль; при закрытии приложения или смене хоста мониторинг прекращается. Включайте системные уведомления только при необходимости.

Профили, история и пользовательский скриншот находятся в пользовательской папке конфигурации Windows (`%APPDATA%\ESXi-RAID-Assistant`); интерфейс WebView2 использует пользовательский cache. Скачанный VIB и инструкции — в `%USERPROFILE%\Downloads\ESXi-RAID-Assistant\<сеанс>`. Имена, адреса, скриншоты и отчёты могут содержать внутренние сведения. Перед Telegram подтвердите передачу части текста стороннему сервису. Пароли не включаются в профиль или отчёт; пароль SSH при включённом мониторинге хранится только в памяти до остановки.

## Проверка и разработка

```sh
cd raid-assistant
go test -race ./...
go vet ./...
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -ldflags '-s -w -H windowsgui' -o ESXi-RAID-Assistant.exe ./cmd/raid-assistant
```

`go run ./cmd/preview` запускает **только демонстрацию** с вымышленными данными: к ESXi она не подключается и ничего не устанавливает. Запускайте только в доверенной сети. UI-тесты: `npm ci && npm run test:ui` (нужен Chromium Playwright). GitHub Actions выполняет Go/race/vet, браузерные сценарии, подписанную Windows-сборку и на Windows runner нажимает настоящую форму WebView2 с локальным имитатором ESXi (успех, отказ, ошибка входа и недоступный хост). Модификации WebView2 и лицензия: [third_party/go-webview2/LOCAL_CHANGES.md](third_party/go-webview2/LOCAL_CHANGES.md).

Иконка находится в `assets/raid-assistant.ico` и в ресурсе `cmd/raid-assistant/raid_icon_windows_amd64.syso`. Инструкция по воспроизведению ресурса из PNG — в `assets/generate_icon.py`.
