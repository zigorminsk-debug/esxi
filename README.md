# MikroTik Lab

Начальная версия автономного русскоязычного учебника RouterOS 7 и планировщика сети для Android и Windows. Интерфейс работает локально, введённые данные никуда не отправляются. Для просмотра без сборки откройте `src/index.html` в браузере; для Windows также можно запустить `npm ci && npm run desktop`.

## Возможности и ограничения

Учебник содержит обзорные инструкции и ссылки на документацию. Картинка на главной — схема, **не скриншот** WinBox. Реальные скриншоты и подробные пошаговые руководства для всех версий и моделей ещё не добавлены. Планировщик проверяет формат и пересечение подсетей, основные поля и некоторые зависимости; он **не эмулирует RouterOS**, не моделирует трафик и не подтверждает работоспособность. Он не генерирует готовую конфигурацию, не задаёт диапазоны DHCP и не покрывает все варианты VPN, маршрутизации, NAT и резервирования. План требует ручной доработки под устройство и проверки на реальном оборудовании. Пароли вводить в приложении не нужно.

## Сборка

GitHub Actions запускается при push в ветку проекта и публикует артефакты Windows (NSIS, без цифровой подписи) и Android (подписанный APK). Сборка Android намеренно завершается ошибкой без секретов: случайный ключ не подходит для постоянных обновлений.

Создайте один постоянный ключ в безопасной среде с установленной Java:

```sh
keytool -genkeypair -v -keystore mikrotik-release.jks -alias mikrotik -keyalg RSA -keysize 3072 -validity 10000
base64 -w 0 mikrotik-release.jks
```

В настройках репозитория GitHub → Settings → Secrets and variables → Actions добавьте `ANDROID_KEYSTORE_BASE64` (результат base64), `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS` и `ANDROID_KEY_PASSWORD`. Надёжно сохраните файл ключа и пароли вне репозитория: потеря ключа сделает обновление поверх существующей установки невозможным. Не публикуйте ключ в Git: любой получивший его сможет подписывать поддельные обновления. После настройки секретов повторно запустите workflow. APK обновляется поверх предыдущего при сохранении package ID `by.mikrotiklab.guide`, ключа и увеличении Android versionCode; в CI versionCode задаётся номером запуска GitHub Actions; при повторном запуске того же workflow он не увеличивается.

Для тестов: `npm test`. Android-проект генерируется в CI из Capacitor; нужны Android SDK и JDK 17. Windows-сборка не подписана сертификатом Authenticode и может вызвать предупреждение SmartScreen.
