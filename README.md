# MikroTik Lab

Начальная версия автономного русскоязычного учебника RouterOS 7 и планировщика сети для Android и Windows. Интерфейс работает локально, введённые данные никуда не отправляются. Для просмотра без сборки откройте `src/index.html` в браузере; для Windows также можно запустить `npm ci && npm run desktop`.

## Возможности и ограничения

Учебник содержит обзорные инструкции и ссылки на документацию. Картинка на главной — схема, **не скриншот** WinBox. Реальные скриншоты и подробные пошаговые руководства для всех версий и моделей ещё не добавлены. Планировщик проверяет формат и пересечение подсетей, основные поля и некоторые зависимости; он **не эмулирует RouterOS**, не моделирует трафик и не подтверждает работоспособность. Он не генерирует готовую конфигурацию, не задаёт диапазоны DHCP и не покрывает все варианты VPN, маршрутизации, NAT и резервирования. План требует ручной доработки под устройство и проверки на реальном оборудовании. Пароли вводить в приложении не нужно.

## Сборка

GitHub Actions запускается при push в ветку проекта и публикует установщик Windows и APK Android. Для прототипа применяются ключи из репозитория; подробности и существенные ограничения безопасности ниже. VersionCode Android задаётся номером запуска GitHub Actions; повторный запуск того же workflow его не увеличивает.

Для тестов: `npm test`. Android-проект генерируется в CI из Capacitor; нужны Android SDK и JDK 17. Windows-сборка использует самоподписанный сертификат и может вызвать предупреждение SmartScreen.

## Подпись прототипа без секретов

На текущем этапе в репозиторий намеренно включены постоянные файлы `signing/android.p12` и `signing/windows.p12`. Workflow использует пароль `prototype-only-change-for-production`; Android alias `mikrotik`. Android APK будет подписываться одним ключом между запусками, что позволяет обновлять установленное приложение при сохранении ID и увеличении versionCode. Windows подписывается самоподписанным сертификатом: такая подпись НЕ удостоверяет издателя и Windows/SmartScreen продолжат показывать предупреждения. Доверенная подпись Windows требует приобретения сертификата у удостоверяющего центра.

**Ключи публичны и скомпрометированы по определению.** Любой, кто получил доступ к репозиторию, может подписать поддельное приложение. Не применяйте этот вариант для выпуска реальным пользователям. Для полноценного выпуска создайте новые закрытые ключи и храните их в секретах или защищённом хранилище. Замена Android-ключа обычно потребует удаления прототипа перед установкой, если заранее не настроена поддерживаемая Android ротация ключей. Не храните реальные данные в прототипе.
